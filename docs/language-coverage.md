# Language coverage

Honest, machine-verified per-language coverage across the **entire** [tree-sitter-language-pack](https://github.com/Goldziher/tree-sitter-language-pack), generated by `scripts/regenerate_language_coverage.py` and continuously enforced by the smoke-tier gate (`tests/test_language_smoke.py`).

Pinned stack: `tree_sitter >=0.25,<0.26` + `tree-sitter-language-pack ==0.9.0` -- the verified-byte-stable pairing. Do not float the pack to >=1.x.

## Headline

- **167 / 167** pack languages **LOAD** (grammar loads + parses a trivial input under the pinned runtime); **0** fail to load.
- **20 RICH** (>= 2 distinct boundary kinds) + **7 SPARSE** (exactly 1 kind) extraction-verified on a curated valid sample.
- **15 EMPTY** (parse clean, 0 boundaries) and **5 EXTRACTION-GAP** (chunker advertises the extension but no parser resolves -- a real, fixable bug surfaced here).
- **125 LOAD-ONLY** -- the long tail with no curated sample, honestly *not* extraction-tested rather than guessed.

## Honest tiers

1. **12 deep golden** -- full byte-level golden conformance + determinism gate (`tests/test_boundary_ir_golden_snapshots.py`): `c`, `cpp`, `csharp`, `go`, `java`, `javascript`, `kotlin`, `php`, `python`, `ruby`, `swift`, `typescript`.
2. **Extraction-verified** -- RICH + SPARSE above: a real boundary surface on a valid sample, kind-set asserted by the smoke gate.
3. **167 load-verified** -- every pack grammar loads under the pin; forward ABI drift fails the smoke gate loudly.

## Named broken / sparse / gap languages (no inflation)

**EXTRACTION-GAP (advertised extension, no backing parser -- broken):** `assembly`, `cobol`, `fsharp`, `raku`, `restructuredtext`. chunker's `EXTENSION_MAP` routes these file types to a language name the parser layer cannot resolve; the IR records `boundary.parse_error` ("Language 'X' not found") and emits 0 nodes. `asm`/`rst` exist in the pack under different names (name-mapping gap); `cobol`/`fsharp`/`raku` have no pack grammar at all. Surfaced here, not patched (this PR does not change extraction behavior).

**EMPTY -- genuine extraction gaps (code that parses but yields no boundaries):** `erlang`, `fortran`, `lua`, `nim`, `pascal`, `perl`, `powershell`, `verilog`, `vhdl`, `zig`. These are real source languages whose grammar loads and parses cleanly, but chunker emits no boundary nodes for them today.

**EMPTY -- expected (data/markup, no function/type surface):** `css`, `html`, `json`, `latex`, `markdown`. 0 boundaries is correct for these formats.

**SPARSE (1 kind -- thin surface):** `bash`, `elisp`, `julia`, `matlab`, `r`, `vim`, `xml`. Mostly single-construct (function-oriented) languages where 1 kind is the honest ceiling.
