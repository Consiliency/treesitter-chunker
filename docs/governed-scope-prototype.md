# Governed source snapshot prototype

`tools/governed_scope.py` is a standalone stdlib tooling driver, not a change to the
published Boundary IR API. Invoke the verified script with `python -I -S`, a closed
request JSON and a new output directory outside the source tree. Both consumers
supply an independently expected driver SHA-256 and policy digest. No parser runs
inside the driver; it stages only selected regular files for the consumer's parser.

The project supplies an ownership assertion and explicit external/unknown rules.
Directory names alone cannot prove ownership. Nested Git roots and submodules are
opaque regardless of common ownership. Symlinks never authorize reading their
targets. No excluded descendant is hashed as source evidence. The external
reference digest records boundary metadata only.

Successful output contains `stage/`, `selection.json`, `selection-receipt.json`
and operational locators. Schema/root/path/metadata failures before classification
are diagnostics only. Classification and copy refusals retain blocked receipts;
partial stages are never parsed. Existing output is never overwritten. Canonical
scope JSON uses the specified Python JSON preimage, not the Spec canon profile.

Directory traversal recurses once per directory level. Scope depth therefore has
no declared limit of its own; the interpreter recursion limit sets it. With
CPython's default limit (1000), trees about 1000 directories deep fail before
selection. The driver exits 2 with `scope_setup:RecursionError` on stderr and
publishes no selection. It does not truncate the tree or return a partial stage.
Deeply nested request JSON follows the same limit. Treat this as a documented
operational bound, not a scope rule or refusal reason.

This is a quiescent-snapshot contract, not protection against a hostile concurrent
filesystem writer. Unsupported no-follow platforms refuse. Legacy extraction
remains unchanged and is not claimed to enforce this scope. Run the dedicated
conformance test from the locked environment; Linux no-read tests trace the actual
child with strace and require that tool rather than crediting an unobserved run.

Consumer test transports are generated byte copies of this script with an explicit
SHA-256 binding. They are test data only: production callers never discover or
silently fall back to them. Refresh from this owner source after a reviewed change.

## Committed boundary policy (opt-in)

A request opts in only with declaration `"version": "governed_scope.v2"` and
`"policy_version": "committed_boundary.v1"`; `governed_scope.v1` requests keep the
`single_repo.v1` behavior and no request is upgraded automatically. A v2 declaration
adds `boundary_transitions` rows `{prefix, decision_ref, kind: "nested_repository"}`.
Its `root_metadata` is `scope_root_metadata.v2`: `object_format` (`sha1`/`sha256`),
full lowercase `commit` and `tree` ids, committed `gitlinks` `{path, object_id}` and
the committed root `gitmodules_blob` (or null). A trusted controller derives that
metadata from an independently identified Git object store; the driver never runs
Git and never reads any `.git` entry.

The declaration's `source_revision` must equal the commit, the working `.gitmodules`
blob id must equal `gitmodules_blob`, and its paths must equal the gitlink paths;
otherwise `scope_metadata` with no output. Directories are classified by rule first.
An included directory with any `.git` entry is never listed or descended into: it
refuses `scope_boundary_uncommitted` with a blocked receipt unless a transition
ratifies that exact path, which records an opaque `nested_repository` boundary and
changes the declaration digest. An unused transition refuses
`scope_boundary_transition`. Outputs use `scope_selection.v2` and `scope_receipt.v2`.

The policy binds boundary metadata only. Dirty tracked bytes and untracked regular
files are not bound to committed blobs; consumers needing committed content stage a
clean committed snapshot. The driver hash changed once for this policy; consumer
copies and pins change only by owner-approved refresh. The no-read tests require
`strace` on Linux.

## Reference commitment producer

A trusted controller, never a candidate or the driver, runs `python -I -S tools/governed_scope_commitment.py commit --git-dir <absolute bare store> --commit <full id> --expected-tree <full id> --output <absolute absent path>`
with an independently identified, controller-owned bare store and independently expected ids. It reads Git objects only: never a working tree,
gitdir pointer, hook, replace ref, lazy fetch or network. Before traversal it refuses alternates, http-alternates, include/includeIf, core.worktree,
worktreeConfig and alternateRefsCommand. It writes exact `scope_root_metadata.v2` JSON by exclusive create (mode 0600) and prints a canonical receipt with the
metadata digest and producer SHA-256. Refusals exit 1 with `scope_diagnostic.v1` and leave existing output untouched; other setup failures exit 2, and unconfirmed Git cleanup or unprovable failed-write cleanup exits 2 `scope_setup:CleanupUncertain`, never success; a failed write removes only its own identity-proven new file.
It is a private opt-in tool with no consumer adoption; it binds boundary metadata only, not file content, and is no hostile-repository sandbox; an equivalent producer must be byte-equal on these vectors.
Ctrl-C limit: the producer does not own SIGINT, so a perfectly timed SIGINT can lose the first error and cut cleanup short; treat any nonzero exit as failure.
