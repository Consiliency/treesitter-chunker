# Detailed plan: boundary-IR determinism gate (extend the golden conformance suite to all languages + add non-empty & pin guards)

## Task
Add a "determinism gate" to treesitter-chunker that makes silent grammar/runtime drift in the canonical Boundary IR fail **loudly in CI**. Motivating failures this cycle: (1) C# silently emitted `{}` when language-pack shipped an ABI-15 grammar incompatible with the pinned `tree_sitter 0.24`; (2) a `tree_sitter 0.24→0.25` bump silently dropped Python docstrings from the IR. Neither failed loudly. The gate must byte-compare per-language IR against committed goldens, guarantee every supported language extracts non-empty, and fail closed if the pinned grammar/runtime versions drift.

## Research summary
The chunker **already has** a boundary-IR golden-snapshot conformance suite, and it runs in CI — so this is an *extension*, not a new system:
- `tests/test_boundary_ir_golden_snapshots.py` parametrizes over `P0_BOUNDARY_LANGUAGES` and asserts `normalize_ir_for_golden(extract_fixture_ir(lang)) == golden/<lang>.json` (dict equality **and** `dumps_boundary_ir` byte-equality).
- `tests/boundary_ir_conformance.py` defines `P0_BOUNDARY_LANGUAGES = ("python","javascript","typescript","go")` (only 4), `FIXTURE_ROOT = tests/fixtures/boundary_ir/repos`, `GOLDEN_ROOT = tests/fixtures/boundary_ir/golden`, `extract_fixture_ir()` (full IR via `extract_boundary_ir(fixture_path, lang)`), and `normalize_ir_for_golden()` (only rewrites `run.tool_version`). Because the golden is the **full** normalized IR, it already catches field-level drift like the docstring drop — *for the languages it covers*.
- Golden corpus today: `golden/{go,javascript,python,typescript}.json` + `manifest.json` + per-language fixture `repos/`.
- CI runs it via `scripts/run_ci_smoke.py` (referenced in `.github/workflows/ci.yml` around the `run_ci_smoke` step), after `scripts/fetch_grammars.py` + `scripts/build_lib.py`. Deps install with `uv pip install --system -e ".[dev,api,viz,templates,advanced]"`; Python 3.11.
- Pins live in `pyproject.toml` (`tree_sitter>=0.24,<0.25`, `tree-sitter-language-pack>=0.9,<1.0`, with the ABI-pairing rationale inline).
- No automated golden-regenerate script exists (the test's assert message instructs a *manual* regenerate). No version-pin assertion exists. `grammar_available()`/`skip_if_grammar_unavailable()` exist but a grammar can be "available" yet emit `{}` (exactly the C# case), which nothing currently catches.

**The four gaps the gate closes:** (a) coverage — 4 of ~11+ supported languages have goldens; (b) no non-empty/grammar-health guard (the silent-`{}` case); (c) no fail-closed version-pin assertion (the ABI-drift cause); (d) no scripted, reviewable regenerate path.

## Changes

### `tests/boundary_ir_conformance.py` (modify)
- `SUPPORTED_BOUNDARY_LANGUAGES` — **add** — a tuple of the full extractable set proven by spec's multilang work: `("python","javascript","typescript","go","java","cpp","c","ruby","kotlin","swift","php")`. Add an inline comment that **C# is deliberately excluded** until its grammar ABI is fixed (link the C#-ABI memory/PR #78), so its absence is a conscious, documented choice — not a silent gap.
- `fixture_path(language)` — **modify** — accept any `SUPPORTED_BOUNDARY_LANGUAGES` member (currently raises for non-P0). Keep `FIXTURE_ROOT / language`.
- `assert_extraction_nonempty(language)` — **add** — `ir = extract_fixture_ir(language); assert len(ir["nodes"]) >= 1` with a message naming the language; this is the loud guard for the silent-`{}` / broken-grammar case.
- `PINNED_TREE_SITTER` / `PINNED_LANGUAGE_PACK` — **add** — the pin *ranges* read from / matched to `pyproject.toml` (`>=0.24,<0.25`, `>=0.9,<1.0`).
- `assert_grammar_runtime_pins()` — **add** — read installed versions via `importlib.metadata.version("tree_sitter")` and `version("tree-sitter-language-pack")`; assert each is inside the pinned range; fail closed with a message that an unintended transitive bump tripped the gate.
- `extract_fixture_ir(language)` — **modify** — generalize the `go`-only `skip_if_grammar_unavailable` guard: for the gate we do NOT want silent skips on supported languages (a missing grammar should be loud), so within the determinism path call extraction directly; keep `skip_if_grammar_unavailable` available for other (non-gate) tests.

- Add entries for the 7 new languages mirroring the existing `{go,javascript,python,typescript}` expectation shape.

### `tests/test_boundary_ir_golden_snapshots.py` (modify)

### `tests/test_boundary_ir_determinism.py` (create)
- `test_extraction_nonempty[<language>]` — parametrized over `SUPPORTED_BOUNDARY_LANGUAGES`, calls `assert_extraction_nonempty` (loud failure if a language emits zero boundaries — the C#-`{}` class).
- `test_grammar_runtime_pins_match` — calls `assert_grammar_runtime_pins()` (fail-closed version assertion).

### `scripts/regenerate_boundary_goldens.py` (create)
- The deliberate, reviewable regenerate path: for each `SUPPORTED_BOUNDARY_LANGUAGES`, `normalize_ir_for_golden(extract_fixture_ir(lang))` → write `golden/<lang>.json` (UTF-8, `dumps_boundary_ir` formatting). Print a per-language summary. Mirrors the manual instruction already embedded in the golden test's assert message. This is the ONLY sanctioned way goldens change; reviewers see the diff in the PR.

### `scripts/run_ci_smoke.py` (modify)
- Add `"tests/test_boundary_ir_determinism.py"` to the smoke batch list (the golden-snapshot test is already present at ~lines 19–26), so the new guards run in CI.

Behaviors / edge cases to prove the gate **bites** (not just passes):
- **Golden drift caught:** hand-edit one node's `semantic_text` in a committed golden → `test_boundary_ir_golden_snapshot[<lang>]` goes RED with a clear per-language diff. Revert.
- **Silent-`{}` caught:** temporarily add `c_sharp` to `SUPPORTED_BOUNDARY_LANGUAGES` with the ABI-15 grammar installed → `test_extraction_nonempty[c_sharp]` FAILS loudly (vs the old silent empty). Revert.
- **Pin drift caught:** in a scratch venv, `pip install --force-reinstall tree-sitter==0.25.2` → `test_grammar_runtime_pins_match` FAILS closed.
- **Regenerate idempotent:** run the regenerate script twice → second run produces no git diff.

## Acceptance criteria

- [ ] `test_extraction_nonempty` fails loudly if any supported language emits zero boundaries (demonstrated by the C#/ABI-15 simulation above).

- [ ] `scripts/regenerate_boundary_goldens.py` regenerates all goldens deterministically; re-running it produces no git diff (idempotent).
- [ ] The new tests run in CI via `scripts/run_ci_smoke.py`; all pre-existing tests stay green; no extraction behavior changed (guard-only).
