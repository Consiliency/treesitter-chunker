# Detailed plan: BAML structural chunking with an official grammar overlay

## Task and decision

Enable source-exact `.baml` declaration chunks, including BAML 0.20.1 backtick prompts, without changing the pinned Tree-sitter 0.26 / language-pack 1.20 stack or the existing 12-language Boundary IR goldens. Use BoundaryML's official grammar plus a one-rule overlay until BoundaryML/baml#5012 is fixed. Distribute the parser in an **optional, prebuilt companion wheel** so existing `treesitter-chunker` installations remain `py3-none-any` and never need a compiler for unrelated languages.

Tracking: Consiliency/treesitter-chunker#101, BoundaryML/baml#5012, xberg-io/tree-sitter-language-pack#200.

## Research summary

- `BoundaryML/baml-treesitter@276b4d8471f1c2f2ce80f182ab46d171b825f2b7` is the official Apache-2.0 read-only mirror. Its `src/parser.c` reports ABI 15 and loaded under the repo's Tree-sitter 0.26 runtime in an isolated probe. The pinned pack's 371-language manifest has no `baml` entry; the exact-version coverage oracle makes a pack bump a separate project.
- That exact generated C parser recognized `class_declaration`, `type_alias_declaration`, and `function_declaration` in the BAML 0.20.1 release example, but reported `ERROR` at its backtick `prompt:`. The mirror's grammar already has a `backtick_string` production with `${...}` interpolation; only `prompt_field` is restricted to `raw_string`. The repo's `src/` contains no external scanner. The one-rule overlay `field('value', choice($.raw_string, $.backtick_string))` is a **hypothesis to prove**, not yet a verified fix.
- `chunker/_internal/registry.py` owns parser lookup, `chunker/languages/base.py` and `chunker/core.py` select nodes, and `chunker/auto.py` owns file-extension routing. The existing on-demand grammar manager uses unpinned Git and working-directory builds, and its source map is not shipped in the wheel; BAML must bypass it.
- Main package metadata currently says `Requires-Python >=3.11` and uses setuptools. Its release workflow publishes a pure-Python wheel. Replacing that wheel with a native matrix for one optional language would affect every consumer, so the companion package owns native distribution. The overlay is temporary; the companion distribution remains needed until an upstream pack release includes BAML and this repo deliberately migrates its pin.

## Feasibility gate — perform before implementation

In an isolated checkout of the exact mirror commit, change only `prompt_field` to accept `backtick_string`, regenerate with a locked Tree-sitter CLI, and run the upstream corpus plus a curated, non-secret set of current BAML files. Include the BAML 0.20.1 example, multiline/nested interpolation, old raw prompts, adjacent declarations, bigints, generics, CRLF, and non-ASCII text. Record: mirror commit and file digests, one-line overlay diff, CLI package version plus downloaded executable SHA-256, generated `parser.c`/`node-types.json` SHA-256, `root_node.has_error`, `MISSING` nodes, and top-level declaration names/spans. Assert that prompt delimiters and interpolation nodes cover the exact intended original byte ranges, not merely that the root is error-free. Census every top-level `_declaration` alternative against the candidate chunk allowlist. **Stop and amend this plan if any valid fixture still parses with an error, a declaration disappears, prompt/interpolation spans are wrong, or generation reports a conflict or unresolved warning; do not substitute AST recovery or source rewriting.**

Gate result on 2026-09-28: **passed** with the exact mirror commit above and Tree-sitter CLI 0.25.10 (npm integrity and executable SHA-256 in `packages/baml-grammar/pin.json`; executable SHA-256 `de21a99ed95e683526b26eee456e12352752487daed0d20afc85157212ab8e3d`). Regeneration reported no conflict or warning; generated `parser.c` SHA-256 is `8ebd06974ee7e4fcca4d5c15a278fce768bd5c91241edf35483b953c537ffd27` and `node-types.json` SHA-256 is `c6d9116d4ac95c82fe1a929f84ed41631d2c57e927fdb3815b0d5598eede3111`. All 65 upstream corpus cases and six focused fixture files parsed cleanly. The fixture gate checked no `ERROR`/`MISSING`, top-level declaration names and byte spans, original prompt/backtick delimiters and interpolation spans, including CRLF and non-ASCII. `_declaration` has 14 alternatives: the initial 12 structural kinds below, plus `let_declaration` and `empty_statement` intentionally excluded from declaration chunks. `dynamic_type_declaration` and `associated_type_declaration` are nested alternatives. `implements_for_declaration` lacks a `name` field; PR B's language-level resolver now owns its stable name. The gate evidence is reproducible from the vendored hashes and tests in PR A.

## Changes and ownership

Use two bounded PRs. PR A is a standalone grammar distribution with no change to the main wheel. PR B adds chunker integration only after PR A's companion version is published through a configured PyPI trusted publisher. Publication is an explicit release step, not implied by this plan artifact.

## Dependencies and verification

1. Feasibility gate, then PR A. If `abi3` compatibility fails on any supported Python, amend PR A to version-specific wheels with a measured matrix; never publish a universal wheel missing the parser. Keep PR A build-only until the new PyPI trusted publisher is configured and the full wheel set passes. Pin the companion tests to the main package's Tree-sitter 0.26 runtime.
2. Publish the reviewed companion version, then PR B can pin it. Verify optional install and base install separately. If upstream fixes BoundaryML/baml#5012 first, compare the new grammar's fixture output to the overlay and remove only the overlay with a reviewed diff. Keep the companion until xberg-io/tree-sitter-language-pack#200 ships, the main pack pin/coverage is deliberately updated, and the registry migration is tested: prefer the new pack grammar only after BAML golden parity is shown; keep the old extra version installable for already-locked clients through a documented transition window.
3. Use a private `$WORKTREE_ROOT` implementation worktree. Run the narrow checks first, then AGENTS.md's local CI loop and Windows preflight. For PR-head Windows/macOS verification, use isolated checkouts at that head rather than updating the remote machines' main checkout. Existing main release validation remains a gate.

uv run --all-extras python scripts/check_baml_grammar.py

PR A additionally runs its own `python -m build --sdist`, locked grammar regeneration, `cibuildwheel` matrix, `twine check`, sdist-to-wheel rebuild, and installed-wheel BAML fixtures on each required platform/Python tuple. PR B runs a **wheel-only** (`--only-binary=:all:`) install of the published main package with its BAML extra on Linux glibc x86_64/aarch64, macOS x86_64/arm64, and Windows x86_64 for Python 3.11–3.13. Parse outside checkout with network unavailable at parse time. A base wheel without the extra must still parse Python/JS and must process a mixed Python/JS/BAML repository without a new fatal error: zero-config falls back for `.baml`, and the repository processor skips it. Record wheel/sdist filenames and SHA-256 values, fixture/generation report, OS/Python CI URLs, and the PyPI companion version on Consiliency/treesitter-chunker#101. Inspect the diff for unintended changes to pack/runtime pins, coverage JSON, or Boundary IR goldens.

## Acceptance criteria

- [ ] The feasibility report proves that the exact one-rule overlay produces clean ASTs and intact declaration spans for current BAML fixtures; otherwise implementation stops for plan amendment.
- [ ] The companion package has provenance-checked generated C, an ABI-15 parser, tested `abi3` wheels on the supported OS/Python matrix, an equivalent sdist build, and no runtime compile/network requirement for wheel users.
- [ ] `pip install treesitter-chunker[baml]` yields named, source-exact BAML declaration chunks through explicit, auto, repository, and streaming routes; malformed files fail before any chunks from that file escape, while other repository files remain usable.
- [ ] `pip install treesitter-chunker` remains `py3-none-any`; without the extra, zero-config text-falls-back for `.baml` and the repository processor skips `.baml`, while explicit BAML calls give actionable install guidance. With the extra, malformed BAML fails per file across zero-config, repository, and streaming routes. Main Tree-sitter/pack pins, pack census, and 12-language golden contract remain unchanged.
- [ ] Local CI-equivalent checks, clean-install checks, the companion wheel matrix, and Windows/macOS PR-head preflights pass. Issue evidence and docs state that only the grammar overlay is temporary; separate native distribution lasts until an upstream pack migration.
